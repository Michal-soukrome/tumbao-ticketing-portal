# Copilot Instructions - Tumbao Ticketing Portal

## Project Overview

This app is a single-event ticketing portal for the Galavečer Tumbao 2027 event. The customer flow focuses on seat selection, reservation, checkout, and QR ticket handling. The staff flow includes admin views and ticket validation.

## Main Features

- Interactive SVG seating map with pan and zoom
- Available / held / sold / selected seat states
- Seat selection with immediate summary and total
- Atomic seat reservation flow with timeout handling
- Session restoration for active holds
- Payment and ticket issuance flow
- Admin order and scanner workflow

## Architecture Decisions

- React + TypeScript + Vite for the frontend shell
- TanStack Query for server-backed seat and order state
- Local component state for the current selection set
- SVG seat map rendered from data, not a static image
- Holds and payments are treated as server-authoritative state

## File Reference Guide

- src/routes/event-page.tsx: customer event page, selection state, reservation flow
- src/components/seat-map.tsx: map rendering and seat interaction behavior
- src/services/ticketing-service.ts: frontend service contract
- src/test-mode/mock-ticketing-service.ts: demo service used for local flows
- supabase/functions: server-side seat and reservation logic
- tests/e2e/purchase-flow.spec.ts: end-to-end user journeys

## Known Quirks

- Selected seats are toggled in place: clicking a selected seat again removes it from the selection set.
- Seat selection stays capped at 10 seats per order.
- Held seats are restored from stored order credentials when the user returns to the event page.
- The seating map uses seat IDs for stable interactions and accessibility checks.

## Tips for Complex Logic

- Keep selection updates functional and immutable when using React state sets.
- Use the seat ID as the canonical key for selection, not array index.
- Preserve server validity checks even when the UI allows deselection or re-selection.
